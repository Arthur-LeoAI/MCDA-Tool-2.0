# S6 design note: conclusion page and report v2

- Status: done
- Based on: PRD F6.1, F6.2; technical design §3.4, §5; ADR 0007, ADR 0008

## Problem

The current results page has only charts and tables. Users still have to answer for themselves "which one is recommended, why, and how reliable is that". The Excel report also contains only calculation results, without recording how the data was handled or where the weights came from. S6 adds both parts and removes old endpoints that are no longer used.

## Conclusion points (backend)

`mcda_core.project.conclusions` computes **structured points** from the weighted-sum result (ADR 0007):

| Field | Content |
|---|---|
| `winner`, `runner_up` | id and score (0–100) of the first and second place. The calculation needs at least 2 eligible alternatives, so there is always a second place; ties are resolved by alternative order |
| `score_gap` | The score difference between the two |
| `tied` | Alternatives tied with the first place (excluding the first place itself) |
| `top_contributions` | The 3 criteria contributing most to the first place's score: w_j · V_winner,j, multiplied by 100 |
| `advantages` | Advantages over the second place: d_j = w_j · (V_winner,j − V_runner,j) × 100, the 3 largest positive values |
| `disadvantages` | The 3 negative values with the largest absolute value |
| `caveats` | Points the user should be warned about, each a code plus parameters |

Only the weighted sum is an additive model, so only there can advantages and disadvantages be split exactly per criterion. The conclusion is therefore based on the weighted sum, consistent with technical design §3.4.

**Caveats**:

| Code | When it appears |
|---|---|
| `caveat_tied_first` | An alternative is tied with the first place |
| `caveat_imputed` | Missing values were filled in (the affected criteria are listed) |
| `caveat_constant` | A criterion with weight greater than 0 has the same value for all eligible alternatives and does not discriminate |
| `caveat_ahp_inconsistent`, `caveat_ahp_inconsistent_groups`, `caveat_ahp_inconsistent_criteria` | The pairwise comparisons within a group, between groups, or among ungrouped criteria have CR > 0.1 |
| `caveat_methods_disagree` | Other methods enabled in expert mode give a different first place |
| `caveat_excluded` | Alternatives were excluded by hard constraints or by missing-value handling |

Like the error codes, these codes are kept in the backend's `MESSAGES` (in English) and translated by the frontend; `errors.test.ts` checks that every code has both Chinese and English text.

**Confidence** comes from the S5 robustness analysis (`confidence` of `/projects/robustness`). It is slow, so it is not part of `/projects/evaluate`; the results page requests it separately and then writes it into the text together with the points.

`/projects/evaluate` gets a new field `conclusion`.

## Conclusion text (frontend)

`frontend/src/i18n/conclusion.ts` turns the points into a few paragraphs using fixed templates, one set each for Chinese and English, without calling a large language model. The same points always produce the same text. The content, in order:

1. Recommendation: "Recommend {winner}, score {score}, {gap} points above second place {runner_up}." (one template per language; a different sentence is used when tied for first)
2. Reasons: the criteria that contribute most to the score.
3. Compared with the second place: where the advantages are and where the disadvantages are (stated explicitly when there are no disadvantages).
4. Confidence: the level and the probability of being first, plus the sampling mode.
5. Caveats: one sentence per caveat. Excluded alternatives and their reasons are still listed separately below.

When the gap is very small (< 1 point), the first sentence warns that "the gap is very small".

The results page shows a "Conclusion" card at the top.

## Excel report v2

`POST /api/v1/projects/report` gets new parameters:
- `conclusion`: the conclusion text already generated by the frontend (in the UI language), written into the "Conclusion" sheet. This way the report and the UI show exactly the same text, and the templates are maintained in one place only;
- `include_robustness`: default true.

Sheets (headers in English, consistent with the existing report):

| Sheet | Content |
|---|---|
| Conclusion | Conclusion text; table of points (first place, second place, gap, confidence, probability of being first) |
| Results | Unchanged |
| Data handling | For each criterion: group, type, unit, value function and parameters, missing-value handling; hard constraints; excluded alternatives and reasons; filled-in missing values |
| Weights | For each level: method (direct, ranking with formula, pairwise comparison), each item's local and final weight; CR of pairwise comparisons |
| Robustness | Sampling settings; for each alternative the probability of being first, mean rank, and probability of each rank |
| Stability, Pareto, Decision | Unchanged |

## Removing old endpoints (ADR 0008)

The frontend now uses `/projects/*` and `/tables/*` exclusively. Removed: `/problems/validate`, `/problems/import`, `/evaluate`, `/pareto`, `/sensitivity/stability`, `/export/problem`, `/export/report`, plus the request and response models used only by them. Kept: `/health`, `/methods`, `/template`. The corresponding API tests now target the project endpoints; the tests of the calculation core are unchanged.

## Verification

- Backend unit tests: hand-calculated values for contributions, advantages and disadvantages; tie for first; the trigger condition of each caveat; the report's sheets and key cells; old endpoints return 404.
- Frontend unit tests: several cases of the Chinese and English conclusion text (normal, tied, very small gap, no disadvantages); the same input produces the same text.
- End-to-end test: the results page for the example data shows the conclusion and confidence; the downloaded report contains the new sheets.
